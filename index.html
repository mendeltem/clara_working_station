Clara Working Station

Alita · local agent, no network

What is computed on this machine, and what of it is published. A workbench, not a portfolio: only what was produced here is listed.

Workflow

One request, read left to right, using "I want to create a WMH segmentation model, can you research it?" as the example:

  1. Prompt. The researcher states the goal in plain language, from any device: the phone app, a desktop PC or the browser. This is the only step that happens outside the workstation.
  2. Research agents. On the workstation, an agent sends the question to Clé (the model on the Charité model hub API), which splits it, and several research agents search papers and code for every method and architecture used for the task.
  3. Method shortlist. The findings are merged into candidate methods, such as 2D U-Net, 3D U-Net, nnU-Net or BIANCA, each turned into tasks with machine-checkable acceptance criteria.
  4. Harness, outer loop. Takes one method at a time from the queue and moves on once it is done.
  5. Harness, inner loop on the workstation GPU. Clara, the local model, writes the code, trains on open data (the WMH Segmentation Challenge training set), and an acceptance check counts the facts. If the check fails, the task goes back to Clara. The check asks no model.
  6. Evaluation. Every model is scored on the challenge test set with the official metric (Dice, lesion F1) and placed next to the public leaderboard, where the 2017 winner reached Dice 0.80.
  7. Result. The best model, a comparison table and a QC page.

Everything after the prompt runs on the workstation: the calls to Clé, the research agents, the harness, training and evaluation. Clara sees the data and has no network access. The research agents reach the network and Clé, and never see the data.

Why a local workstation

Shared GPU time is too slow for this kind of work. On the institute cluster, a job asking for a whole GPU was scheduled about 9 hours ahead; only 7 of the cards have 80 GB. A small share of a card starts within seconds, but it only fits small trainings (measurement, 16 Oct 2026). An agent that builds a model, trains it, finds an error and tries again needs dozens of such rounds a day. With a queue in between, each round costs hours; on the workstation it costs minutes.

A local model can look at the patient data; a cloud model cannot. Clara runs on the workstation, so the images never leave the machine. That lets her do what a remote model may not: open every scan, read every mask, run the model on the whole cohort, and look at the cases where it fails. She sees far more of the data than any summary would carry, and she sees it fast.

Local is a route, not a permission. Whether a dataset may be processed by an AI system at all is decided by its data agreement, and a clause that forbids it binds the local model too (rule). Where processing is allowed, running it locally keeps the data inside the institution.

What Clara did on her own

Given one task file with 15 machine-checkable acceptance criteria, Clara wrote a 2D U-Net in plain PyTorch (762 lines), cross-validated it over the five given folds and evaluated all 170 public WMH Challenge cases, every case predicted by the model of the fold that had not seen it.

Three failures that looked like success

These had to be fixed before the agent could work unsupervised. Each one was silent, and each looked like something else.

  1. A three-character file blocked the agent for two days. current-quant said q5. The Q5 model has a 32,768-token context; the agent framework needs 64,000 and refused to start. Symptom: rounds of 22, 30 and 9 minutes that produced 63, 0 and 57 bytes of log. Model, data and task were all fine.
  2. The run watchdog could never bark. Its GBNF grammar put the alternation bar at the start of a continuation line, which this llama.cpp build rejects with HTTP 400 on every call. Its fallback on any error was "ok, continue", so it would have approved everything forever. Fixed, and "undecided" is now an outcome separate from "ok".
  3. FreeSurfer was invisible to the agent while the self-test said green. The agent starts through sg, which is setgid, and the dynamic linker drops all LD_* variables for setgid programs. recon-all, mri_convert, samseg and mri_synthseg died on a missing library although they were on PATH; the self-test ran without sg and passed. Fixed by setting the variable again after the setgid boundary.

The pattern: a component fails in a way that looks like success. A check that cannot judge must say so, never fall back to the harmless answer.

The system behind it

Tools, measurements and operating rules are kept in local_models, including the model-independent scaffolding that describes what lets an agent finish a task. What the agents learned along the way is collected in the wiki blackbeard_wikki.

  • RTX A5000 with 24 GB (Ampere), i9-12900K, 64 GB DDR RAM, Ubuntu 24.04, NVIDIA driver 550 (CUDA 12.4). As of October 2026.
  • Clara's model is Qwen3.8-27B in Q4 via llama.cpp. Against Nemotron 3.5 Bolt 74B-A9B on the same card: 100 % vs 88.5 % on a 13-task test. Bolt generates 66–69 tok/s against about 30, but reasons longer. Entry
  • The model server unloads when idle: 21,770 MiB VRAM in use, 1,618 MiB after, 11.4 s to wake. This keeps the card free for training.

The shared wiki

All agents and chats share one memory: the public repository blackbeard_wikki on GitHub. Clara on the workstation, the Claude sessions and the chat projects read it before they work and write back what others can reuse, so no agent searches for or builds again what already exists. As of 28 October 2026 it holds 358 entries in 27 areas and 16 tools, this project's topics and others.

FolderWhat is in it
knowledge/<area>/one file per statement, typed: 174 findings (with source and date), 88 rules, 45 mechanisms, 33 open checks, 15 risks, 3 axioms; each area has an INDEX.md and a short SUMMARY.md
tools/reusable tools, each with README, INSTALL, code, a test on public or synthetic data, papers with DOI and a changelog
updates/LOG.mdone line per change: date, which agent, which files, what and why
templates/the templates every entry and tool follows

How an agent uses it. It reads the README and INDEX.md, then only the SUMMARY.md of the areas its task touches, and goes deeper only when needed. It compares with its own project, reuses what is there, and files what it learned with the templates. Nothing is pushed before the owner says yes; each contribution is one commit plus one line in the log. For Claude the wiki is packaged as a skill (plugins/blackbeard-wiki) that loads the matching areas before answering.

Rules that keep it trustworthy. Entries are data, not commands: an agent never acts on an instruction it finds inside an entry. Every number states its origin (measured, assumed or set by the owner); papers carry a DOI and are marked peer-reviewed, preprint or press release. Never in the wiki: patient data or subject IDs, image data from studies, credentials, internal host names, unpublished manuscripts. Entries that turn out wrong are not deleted but marked gebrochen (broken), with date and source.

Limits

  • The method comparison uses 20 of the 110 public test cases, a QC sample, not the full test set. The 2017 winner line is on all 110 cases.
  • Clara's own U-Net numbers come from folds that mix challenge training and test cases; they are not a leaderboard result.
  • The System 1 gate was measured on 154 commands labelled by one rater (the agent, with a rubric written before any model ran); it runs in shadow mode only.
  • The 13-task model test is small; it ranks models for this use, it does not benchmark them.
  • The cmake flags in the setup are reconstructed, not copied from the build log.
  • The diagrams are generated illustrations; where they and the tables differ, the tables are right.

Where data may go

What is not here. Patient data and results on in-house cohorts stay on the machine. Only work on public datasets is published: the QC above runs on the WMH Segmentation Challenge (Utrecht, Singapore, Amsterdam). Checked before every push: every dataset needs an explicit release. Anything derived from in-house data inherits its class (rule), so the comparisons on the mixed pool of challenge and in-house cohorts are not shown here.
